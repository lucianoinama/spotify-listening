# Power BI dashboard

A five-page Power BI Project (PBIP) on top of the `marts` schema of this repository's
warehouse. Report and model are plain files, generated by `build/build_pbip.py`.

| Page | Question |
| --- | --- |
| Resumen | How much do I listen? KPIs, hours per day, top artists and genres, top album of the last 30 days with its cover |
| Cuándo escucho | When do I listen? Heatmap by weekday and hour, peak hour, time of day |
| Artistas y géneros | What dominates? Monthly rankings, artists per genre, artist detail |
| Canciones | What do I play? Top tracks, release decade, play source, explicit content |
| Álbumes | What do my top albums look like? Gallery of the 8 most played covers |

The design is in [specs/spotify-listening.md](specs/spotify-listening.md), including the
decisions that depart from the template's rules (one decimal on hours, natural sort order on
ordinal axes, Spanish names).

## Open it

1. Start the warehouse: `docker compose up -d postgres` from the repository root.
2. Open `SpotifyListening.pbip` in Power BI Desktop. The project has no cached data.
3. Click **Refresh**. Power BI asks for credentials once per data source: choose the
   **Database** tab, user `spotify`, the password from your `.env`. Accept the unencrypted
   connection (a local container without TLS).
4. After new data arrives the `transform` service rebuilds the marts by itself (see
   `docker compose logs transform`); then Refresh again in Power BI.

Credentials are never stored in the project. The server is `localhost:5432` and the database
`spotify`; to change them, edit `PG_SERVER` and `PG_DATABASE` in the build script and rebuild.

## Change it

Edit `build/build_pbip.py`, not the generated files, then:

```bash
python build/build_pbip.py
```

Validate before opening Desktop:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\validate-json.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\validate-pbip.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Test-PbipSemantics.ps1
```

## Status

The three validators pass, and the report was opened in Power BI Desktop 2.159, refreshed
from the warehouse and reviewed page by page on 2026-11-06. It is not verified with the
template's Desktop Bridge loop, which needs two extra npm packages. Open items are in the
spec, section 7.

Do not save the report from Desktop unless you mean to: saving rewrites the generated files.
Change `build/build_pbip.py` and rebuild instead. If you do save, rebuild to restore them.

## Origin of the agent context

`AGENTS.md`, `CLAUDE.md`, `copilot-instructions.md`, `.claude/skills/`, `.github/agents/`,
`.github/instructions/`, `docs/AI-CONTEXT.md`, `specs/` and the PowerShell scripts come from
[Mofaji/Agentic-PBIP-Template](https://github.com/Mofaji/Agentic-PBIP-Template) (MIT, see
`LICENSE-Agentic-PBIP-Template`).

Deliberately left out: `.claude/settings.json` (the hooks and pre-approved commands), the
template's tests, its Python examples and its CI. `scripts/hooks/` is kept as reference but
nothing runs it. The skills load automatically only when Claude Code is started from this
folder.
